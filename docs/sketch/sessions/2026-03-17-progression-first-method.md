# Session note: progression-first design method

Date: 2026-03-17
Branch: `dev`

## What changed

- We corrected the planning method itself.
- We will no longer invent representations first and justify them afterward.
- We will derive representations from a narrated duel progression.

## Working rule

At each step of the narrated duel progression, record only:

1. what must already be true
2. what happens
3. what changes

If that is expressible concretely, do not add a new abstraction.

## Immediate implication

- Some previously written abstractions remain plausible, but are only provisional now.
- The next planning task should be a literal walkthrough from duel start to the first state change.
